# Дополнительная проверка перед сдачей

Автор проекта — Иван Лазичный.

Здесь сохранены новые реальные API-запуски после исправления диагностики и протокола воспроизведения. Исходное сравнение baseline с short_prompt по 40 вопросам × 3 повтора находится уровнем выше. Назначение этого каталога — отдельная проверка диагностики и протокола воспроизведения.

## Состав материалов

| Файл | Что подтверждает |
|---|---|
| [preflight.json](preflight.json) | Реальное подключение GigaChat-2-Max/B2B с проверкой TLS, генерация, native function calling с продолжением истории и state ID, JSON Schema, embedding размерности 2560. Все пять попыток имеют известный usage; всего 315 API-токенов |
| [calibration.jsonl](calibration.jsonl), [сводка](calibration.summary.json), [метаданные](calibration.meta.json) | Новый прогон 20 калибровочных примеров под протоколом v2; все 20 оценок получены, согласие с авторскими метками 100%, kappa 1, ложное принятие 0 |
| [diagnostic_cases.jsonl](diagnostic_cases.jsonl) | Намеренно отобранные 12 вопросов: восемь вопросов с регрессиями в прежнем сравнении и четыре контрольных |
| [validation.jsonl](validation.jsonl), [сводка](validation.summary.json), [метаданные](validation.meta.json) | Один новый запуск выбранного short_prompt на каждом из 12 диагностических вопросов; безопасные причины отклонения и usage сохранены |
| [offline_checks.json](offline_checks.json) | 51 локальный тест пройден, ошибок и пропусков нет; этот этап не обращался к платному API |

Оценочный контур показал стопроцентное согласие судьи с разметкой. Сигнатуры v2 сохраняют настройки, фактические промпты/схемы, данные и параметры калибровки; несовместимые журналы нельзя продолжить как одну серию.

## Что показал диагностический срез

По автоматическому оценщику полезны **8 из 12 ответов**. Формат и цитаты приняты у 10 из 12; две попытки завершились no_valid_candidate после неуспешного исправления цитаты. Расход обработки вопросов — 35 332 API-токена, отдельно модельного судьи — 13 934 токена. Издержки неуспешных попыток включены. Срез выбран **после просмотра прежних регрессий** и специально обогащён проблемными вопросами. Доля 8/12 описывает этот диагностический набор. Сравнение качества до и после выполнено отдельно на 40 вопросах с тремя повторами; назначение этого запуска — проверить исполнение исправленного протокола и наблюдаемость ошибок.

## Что теперь видно в диагностике

В обеих новых неуспешных попытках test-10 и test-33 trace содержит error_type, reasons, ограниченный rejected_public_content, признак обрезки и хеш исходного публичного содержания. Это позволяет отличить конкретное отклонение цитаты от общего no_valid_candidate без вывода внутренних рассуждений и ключей.

Для **test-10** найден нужный фрагмент о 8:30 и «Ленэкспо», но модель изменила написание в цитате: в исходнике `IT- завтрак`, в ответе `IT-завтрак`. Проверка нормализует пробелы, но не считает такую редактуру дословной цитатой. При исправлении дополнительно была предложена строка сессии из метаданных, которой также нет в тексте цитируемого фрагмента. Обе проверки записали quote_not_in_context.

Для **test-33** модель сослалась как на цитату на строку метаданных `ПМЭФ-2015, 18.06, панельная сессия: cybersecurity`. Она не является подстрокой текста указанных фрагментов. Та же ошибка сохранилась после исправления. Кроме того, истинное название панели не попало в найденный контекст, а ответ повторил служебное имя cybersecurity.

Эти причины относятся **только к новым попыткам в этом каталоге**. У семи старых регрессий no_valid_candidate подробности не сохранялись. Новая диагностика не устанавливает причины прежних ошибок задним числом; их ограничения остаются описаны в [исходном разборе](../error_analysis.md).

Полный список — [docs/submission_checklist.md](../../docs/submission_checklist.md). Повторное выполнение `python scripts/verify_submission.py` обращается к API и расходует токены; для чтения этих сохранённых результатов оно не требуется.
