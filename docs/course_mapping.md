Номера ячеек считаются с единицы, включая Markdown, независимо от execution_count.

| Занятие | Опорные ячейки | Применение |
|---|---|---|
| 1 | 25–32, 41–51, 69–75, 134–149 | Шаблоны, Pydantic, JSON Schema, версии, контроль завершения |
| 2 | 51–68, 78–95, 97–108 | Корпус ПМЭФ, EmbeddingsGigaR, отбор контекста, цитаты и трасса |
| 3 | 43–61, 99–110, 138–139 | Self-consistency по фактам, полный бюджет, парные регрессии |
| 4 | 120–135, 71–109 | Проверки поиска, фактов и ответа, калибровка судьи, offline-сравнение |
| 5 | 42–59, 70, 77–90 | Usage, embedding и генерация, тариф с датой и источником, цена полезного ответа |
| 6 | 18–24, 34–42, 51–60 | Лимиты, события, неизвестная полезность отдельно от валидности |

| 8 | 18–21, 45–55, 58–73 | Два инструмента, нативный function calling, state, bounded ReAct |

Особенности переноса:

- Порог HR-корпуса не переносится на ПМЭФ; своя разметка — в data/gold.
- В отличие от демонстрационной таблицы spief_search, генератор получает полный текст выбранного фрагмента.
- Один REST provider заменяет смесь несовместимых версий SDK.
- Usage пишется до валидации; при исключении сохраняется частичная трасса.
- Валидность JSON и полезность оцениваются раздельно; содержательная проверка использует модельного судью и эталоны по источникам.
- Контекст не режется по произвольным 700 символам: выбираются целые фрагменты под бюджетом.
- Строгий кеш учитывает версии и год в вопросе.
- Учебные числа не выдаются за результаты проекта.
